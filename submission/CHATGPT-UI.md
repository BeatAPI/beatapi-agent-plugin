## 状态与版本

当前浏览器私有插件为 1.0.2；已部署的 MCP 主要返回文本和 structuredContent，尚未注册 UI 组件资源。
本机已实现下述组件、输入条件约束与网关资源；尚未推送、部署或更新当前私有插件安装。账户权限未扩大。
建议下一次含组件的私有预览使用 1.1.0；仓库 Node 包的 0.4.0 属于独立版本线，不能机械同步。
公开包版本、网关部署版本和 UI 资源版本应分别记录，并以同一次宿主验收关联。

## 官方依据

- [Add UI](https://developers.openai.com/plugins/build/chatgpt-ui)：UI 可选；优先 MCP Apps 标准，数据与渲染解耦，先用最小内联展示；声明媒体资源 CSP。
- [Reference](https://developers.openai.com/plugins/reference)：工具的 `_meta.ui.resourceUri`、`_meta.ui.visibility`、outputSchema，以及调用前后短状态文字。
- [Build MCP server](https://developers.openai.com/plugins/build/mcp-server)：保留纯工具能力；profile 工具帮助区分多个连接账户；权限必须在服务端逐次验证。
- [Authentication](https://developers.openai.com/plugins/build/auth)：账户识别使用请求的已验证连接，不从聊天文字或组件状态选择其他账户。

## 本版范围

保留 Search -> Inspect -> 显式授权执行 -> 同一任务查询的现有链路，不增加第二套账户、任务或计费系统。
采用一个共享组件的研究结果与媒体任务分支。SEO 是研究结果的展示分支，不另做独立工作台。
报价先采用简短的文本确认；第一版组件只读，不提供直接发起付费生成的按钮。
暂不加入侧边栏、全屏编辑器、文件上传、充值、密钥输入、自动重试或自动换模型。

## 交互

| 阶段 | 用户看到什么 | 边界 |
| --- | --- | --- |
| 免费发现 | 少量匹配能力、可执行性、必要输入和计费单位 | 不把目录当调研结果，不默认展开 schema |
| 账户歧义 | 宿主可辨识的连接名称；确有歧义才询问 | 建议增加官方 profile 工具；不在组件中存凭证或猜账户 |
| 报价 | 输入素材、模型、时长/尺寸/比例、费用及其是精确报价还是估算 | 不展示无关示意图；没有准确总价就说明不确定性；确认前不执行 |
| 提交 | 实际已接受任务和任务设置 | 不把调用结束写成生成完成；不展示管理员通道或凭证信息 |
| 处理中 | 同一任务的当前状态及只读刷新操作 | 无真实百分比就不画百分比；按返回间隔限制手动刷新；不做后台自动轮询 |
| 媒体完成 | 实际图片/视频预览、打开/下载链接、返回用量与设置 | 原生播放控件；不自动有声播放；输入、输出分清；未返回尺寸不声称符合请求比例 |
| 查询完成 | 结论、可核对来源列表、样本范围、市场/语言和数据日期 | 不同来源的事实与模型总结分开，缺失值显示未知，不把预览样本当全量趋势 |
| 失败/过期 | 简短原因、是否已有任务、允许的下一步 | 免费刷新不能变成重跑；余额不足只说明限制；不推广充值或更换凭证路径 |

原始 JSON、schema hash 和调试编号不作为默认主内容；需要排查时提供详情，任务恢复 ID 仍须可取回。
语言跟随用户请求，reference、ID、URL、参数键和枚举值不翻译。
拒绝类提示沿用 1.0.2 的范围规则，简短结束，不用大表格重复罗列无关能力。

## 协议与实现边界

1. MCP 服务端注册有版本号的 `ui://` HTML 资源，MIME 为 `text/html;profile=mcp-app`。
2. 只在现有 `beatapi_get_capability_task` 与 `beatapi_get_capability_result` 挂 `_meta.ui.resourceUri`；不新增渲染工具，也不给付费执行工具挂组件。
3. 组件优先通过 MCP Apps `ui/initialize`、`ui/notifications/tool-result` 和 `tools/call` 接入宿主。只在标准不覆盖时使用可检测的 ChatGPT 扩展，不把兼容别名当主协议。
4. 结构化展示返回值提供准确 outputSchema。`content` 给模型简短结论，`structuredContent` 给可推理数据，组件专用补充可放 `_meta`；隐藏 `_meta` 仍不能存秘密或代替鉴权。
5. 现有读取工具以已拥有的 reference + request/task ID 读取既有结果；组件刷新固定重用当前入参和读取工具，不信任正文 next，不能通过随意传入状态、费用或媒体 URL 来制造权威执行结果。
6. 渲染和刷新继续走现有 OAuth 授权、归属检查和状态/结果读取。过期结果不能通过重新执行恢复，跨账户 ID 必须拒绝。
7. 第一版组件不直接调用任何付费 start 工具。设置修改回到对话确认；后续若加生成按钮，必须另验确认、输入绑定、幂等与防连点，不以按钮点击替代服务端授权。
8. CSP 只列实际使用的媒体域，例如已验证的 cdn.beatapi.io 和 media.beatapi.io；不通配、不内嵌运营后台、不把供应商签名地址或认证信息塞进 iframe。
9. 需要时为工具增加 invoking/invoked 简短文案，例如“正在查找能力”“任务已提交”“状态已更新”。这些是工具调用状态，不是视频任务进度，也不能控制 ChatGPT 全部原生界面。

## 实施顺序与验收

1. 先完成简短回复、价格确认和调用状态文案；组件以媒体任务的只读预览/免费刷新先落地。
2. 再补研究结果视图，复用同一组件框架，不为每个模型/API 建一个页面。
3. 可选增加官方 profile 工具，解决两个连接仅靠 Primary 标签难以辨认的问题；不扩大 scope 或创建新账户。
4. 本机模拟成功、处理中、失败、过期、无媒体、多媒体、缺字段与错误账户；不需要付费生成验证布局。
5. 真实宿主检查内联布局、暗色与窄屏、媒体播放、CSP、来源链接、键盘可用和无组件回退。
6. 核对刷新只读、不会重新扣费、不会触发其他生成，失败结果不被渲染为成功。
7. 部署并重新同步同一私有插件后，在目标版本复验、录制与托管最终演示，再生成正式提交包。

所有模拟素材必须标为模拟，不能混入审核成功证据。现有方形视频可以用来检验播放器与尺寸差异提示，不能据此标记 9:16 用例通过。
本阶段不重新调查那条生产任务，不重新生成，也不默认授权推送、部署或送审。

## 首帧比例修复

用户提供的后台记录确认本次已收到并转发 9:16；问题不是漏参，而是首帧模式跟随 1254×1254 输入图。
公开契约与提交校验同时拒绝 Normal 的 `images + aspect_ratio`，首帧模式不补默认比例；不会悄悄裁图、拉伸或切换模式。
固定比例可以选匹配比例的首帧，或经用户确认使用 `reference_images`/纯文本；参考图不承诺精确第一帧。
MCP 要求明确 duration/resolution，非首帧模式还需明确 aspect_ratio。审核案例已改成用户明确授权参考图模式的新用例，旧失败保留。
面向用户的提示不包含通道、内部插件、服务商身份；组件投影也排除内部路由字段。

## 通用参数架构

链路为：模型交互声明 -> 公开 JSON Schema/说明 -> 免费 Inspect 与用户确认 -> 固定 MCP 输入校验 -> 同源执行校验/默认值 -> 实际结果验收。
`beatapi_generation_interaction.go` 声明哪些设置必须明确、哪些参数由素材派生、何时适用。一个声明同时生成条件 schema、抑制冲突默认值并校验实际请求，不再分别修补 UI 和适配器。
`x-beatapi-agent-input` 是附加的 Agent 确认 JSON Schema；插件编译器只合并 schema，不判断模型名、素材字段名或参数名。新增模型/规则在领域契约内声明，宿主无需新增分支。
第一批统一 H3 Normal、Kling V4、Grok Imagine Video 1.5 已知的首帧继承语义；其他未声明的模型行为不猜测。回归还覆盖不存在于模型清单的参数/模型，验证机制而非单例补丁。
用户选择、服务端默认、素材派生值不能混称。素材无法确定实际尺寸时明确未知，不用指定比例冒充结果。
本机制保证已声明约束的提交一致性，不声称能预知所有服务端执行差异；新模型上线仍须补全真实契约与验收证据。
部署时同步固定目录与对应 schema_hash；若后台选择了上传目录，必须更新该目录，不能只替换内置 JSON。
