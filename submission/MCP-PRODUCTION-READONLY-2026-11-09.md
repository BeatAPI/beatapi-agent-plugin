## 选择与回滚

源码确认：`beat_mcp.catalog_id=0` 读取随网关镜像内置的目录，正整数读取数据库保存的上传目录。上传与启用是两步，上传本身不切流。已装载配置未变时复用运行态，配置变化后下次访问重建；一分钟是构建失败的重试间隔，不是正常目录切换的固定等待时间。多实例还依赖各实例设置同步，须切换后逐实例/重复验收。

后台只读状态接口 `GET /api/beat/mcp/admin/status` 可返回实际 source、ID、摘要及最近 50 个上传版本，不返回目录 Content；当前源码没有目录内容下载路由。

本轮访问结果：

- 公共 api 域该管理路径返回 nginx 404；不是 OAuth 或 MCP 扫描错误的证据。
- `https://admin.beatapi.io` 返回 Cloudflare 520，无法读取真实管理配置。没有绕过访问限制或读取浏览器令牌。
- 因此当前 catalog_id、线上镜像 SHA、实际旧版本可选性、数据库目录原文件备份及多实例配置一致性均未确认。仅凭公开描述符不能补齐这些信息。

真正切换前必须取得：当前状态 JSON、准确旧 catalog_id/摘要、匹配该摘要的旧目录原文件（或明确保留的旧镜像内置版本），以及实际可操作的管理入口。若旧值为 0，升级镜像后“选择 0”会读取新镜像的内置目录，不能把它当成自动恢复旧目录。可在之后授权的发布阶段保留旧镜像并保留旧目录为独立上传版本，验证准确回滚目标；本轮未做上传或回滚演练。

切换影响限于远程 MCP 目录和宿主工具缓存；这些候选文件未改变原 REST、本地三工具、计费、OAuth、任务存储或生成参数处理。但部署仍涉及实例更新，不能宣称对线上零风险。目录回滚不会撤销已经执行的任务，也不会自动更新 OpenAI 已保存的工具快照，仍需重新发现/扫描。
